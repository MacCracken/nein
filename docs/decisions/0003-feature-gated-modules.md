# ADR 0003: Feature-gate optional modules

## Status

**Superseded by the Cyrius port (v1.0.0) — retained as a point-in-time record.**

Everything below describes the Rust implementation: Cargo feature flags, a
`tokio` dependency gated behind `apply`, and a `full` feature. None of it
exists any more. The Rust tree was deleted at v1.6.8; `grep -rn "#ifdef"`
across the Cyrius tree returns zero hits.

**What actually replaced it.** The decision itself — consumers should compile
only what they use — survived; the mechanism did not. nein now ships two
single-file bundles generated by `cyrius distlib` from the `[lib]` and
`[lib.mcp]` module lists in `cyrius.cyml`: `dist/nein.cyr` (the 19-module core,
deliberately free of bote and sigil) and `dist/nein-mcp.cyr` (core + `sign` +
`mcp`, for MCP hosts such as daimon). A consumer picks a bundle rather than a
feature set. CLAUDE.md's "`#ifdef` for optional modules" principle describes
the intended future direction, not current practice.

This ADR is left unedited below per the convention recorded in
`docs/doc-health.md`: ADRs are dated at write-time and superseding decisions
reference the originals rather than rewriting them.

*(original, as written for the Rust implementation:)*

## Context

nein has many modules (NAT, policy, bridge, engine, mesh, config, geoip, MCP)
with different dependency requirements. Consumers like stiva only need bridge
and NAT; aegis only needs builder and geoip.

## Decision

Each optional module is behind a Cargo feature flag. Core types (rule, table,
chain, set, validate, error) are always available. The `tokio` dependency is
only pulled when the `apply` feature is enabled.

Default features include the most commonly needed modules. The `full` feature
enables everything.

## Consequences

**Positive:**
- Consumers only compile what they use.
- `tokio` is not forced on consumers who only render rules.
- Clear module boundaries with explicit opt-in.

**Negative:**
- Feature combinations must be tested (CI tests default, no-default, and all).
- Cross-feature dependencies (e.g., `inspect` requires `apply`) add complexity.
- `ChainRule::Nat` variant is gated behind `nat` feature, affecting deserialization.
