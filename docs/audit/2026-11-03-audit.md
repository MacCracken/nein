# Security Audit — 2026-11-03 (P(-1), v1.8.2)

Scaffold-hardening review per CLAUDE.md's P(-1) process, run against v1.8.1
(cyrius 6.7.18, bote 3.7.6, 394 public fns, 21 modules, 762 + 18 assertions at
review time) — the first full review after three toolchain moves
(6.6.6 → 6.6.20 → 6.7.9 → 6.7.18) and a bote minor-to-minor jump
(3.3.13 → 3.7.6).

**Method.** Five independent reviewers, one per area, each reading its files
cold: the subprocess and syscall layer; nftables injection in the core render
path; the higher-level builders and config; the live-rule parsers; and signing,
MCP and a repo-wide sweep for language-migration traps. Every MEDIUM-or-higher
finding was then **re-verified by the maintainer session, not taken from the
reviewer**: by applying nein's own rendered rulesets with real nftables 1.1.7
inside an unprivileged user + network namespace (`unshare -rn` / `-rnm`), by
live traffic through a bridge / LAN / external topology built in that
namespace, by re-running the reviewers' proofs of concept against both the
1.8.1 and the repaired code, or — where stated — by reading the code. Status
lines below say which.

**Result: 4 HIGH, 18 MEDIUM, 28 LOW** (two of the LOW found during repair by
the new load test). **v1.8.2 fixes every HIGH, 16 of 18 MEDIUM, and 23 of 28
LOW.** Deferred items are listed at the end with their reason and target.

The 2026-08-21 audit's two open MEDIUM: the **pipe-ordering deadlock is fixed**
(S-4); **replay binding is deferred to 1.9.0** by decision, designed with aegis.

## HIGH — all fixed in 1.8.2

### P-1 — `nein_diff` deleted rules in tables the target never mentions
`diff.cyr` `diff_compute`. Every chain on *either* side became a reconcile key,
so a live chain the target did not declare was "out of sync" and every rule in
it was deleted. With nein's `inet filter` fully in sync, a docker-style
`ip nat POSTROUTING` masquerade was deleted (exit 0). stiva, aegis, daimon,
docker, libvirt and kube-proxy sharing a host would each wipe the others'
rules. Latent since 1.5.0; it became live when the 1.6.9 H-2 fix (`-a`) made
the deletes valid.
*Fix:* only chains the target declares are reconciled (an empty target chain
still counts, so a caller can empty its own chain). Also removes the quadratic
key build (P-6).
*Verified:* the reviewer's captured listing (out5) — 1.8.1 emitted
`delete rule ip nat POSTROUTING handle 2`; 1.8.2 emits nothing. Regression test.

### P-2 — rules starting with `counter`, `limit`, `quota`, `ct helper`, … were parsed as block openers
`inspect.cyr` `_classify_block_open`, used by both parsers. The opener check ran
at any depth before the in-chain check, so `counter packets 0 bytes 0 accept`
(nein renders it itself via `verdict_counter()`) opened a phantom block: that
rule and every later rule in the chain vanished. `nein_diff` then appended the
target on every run, which turned the 1.6.10 ordering fix (H-5) back into
append-only. `status()` miscounted (1 of 5 rules).
A regression from the 2026-08-21 H-4 fix.
*Fix:* a line opens a block only when it ends in `{` (handle aside) and sits
where a block can open — `table` at top level, any object directly in a table,
a nested brace in a non-chain object. Inside a chain such a line is a rule with
an anonymous chain. Generic, so `tunnel` and future objects are covered (P-7).
*Verified:* captured listings out1 / out6 — all rules parsed with handles, the
chain rebuilds in order. Regression tests; fuzz harness.

### B-1 — container port publishing captured routed traffic to every destination
`nat.cyr` DNAT render, `bridge.cyr` forward rule. `tcp dport 80 dnat to
172.17.1.2:80` had no destination scope, so in prerouting it rewrote every
forwarded packet to port 80, whatever its real destination.
*Verified live (namespace topology):* a LAN client fetching an external site on
port 80 got the container; another container's own outbound port-80 traffic
timed out; and the container's port was reachable by routing straight to its
address with no DNAT.
*Fix:* every DNAT is scoped `fib daddr type local` (Docker's `addrtype LOCAL`);
the forward accept requires `ct status dnat` (Docker 28's direct-routing fix).
*Re-verified live:* six paths — external traffic not captured, published port
works, direct access blocked, outbound works, cross-tenant blocked, same-tenant
allowed.

### B-2 — the engine's loopback accept cancelled per-agent policy between agents
`engine.cyr`. Each agent chain carried `iif "lo" accept`; traffic between two
local addresses crosses `lo`, so it accepted all agent-to-agent traffic.
*Verified live:* svc-a allows inbound 8080 only; svc-b reached svc-a:22.
*Fix:* the loopback accept names the agent's own address (`iifname "lo" ip saddr
<agent>`; mirrored outbound).
*Re-verified live:* svc-b → svc-a:22 blocked.

### Deferred (decision, 2026-11-03)

> **Status, 1.9.0 (2026-11-03): M-2, M-3 and replay binding are fixed**, together
> with LOW S-8 and B-9 (part) below — see CHANGELOG `[1.9.0]`. M-2: the gate
> permits only on `NEIN_GATE_PERMIT`, installs once, and an ungated host runs only
> the offline tool (a gate per registration is not expressible in the handler
> ABI; replacement is refused instead). M-3: `nein_tool_class` with a
> `READS_LIVE` class and `firewall_read` profile. Replay: the v2 envelope
> (`sign_ruleset_v2` / `verify_ruleset_v2`), as sketched below.

- **M-2** — `mcp.cyr`: the host gate is called through `fncall2`, so a gate
  written to return a `Result` is truncated to its tag and `Err` (tag 1) reads
  as *permit*; and `_nein_gate` is one process-wide variable that a later
  registration replaces. **1.9.0**, with daimon: a permit constant and a
  per-registration gate change the host contract. 1.8.2 documents the hazard in
  `docs/guides/mcp-host-integration.md`. Latent: daimon's gate returns 1/0.
- **M-3** — `mcp.cyr`: `nein_status` / `nein_list` / `nein_diff` read the live
  root ruleset but are classed read-only in the plain `firewall` profile, which
  hosts treat as safe to expose. **1.9.0**, with daimon: a separate read-live
  class / profile. 1.8.2 documents it.
- **Replay binding on signed rulesets** (carried from 2026-08-21) — **1.9.0**,
  designed against aegis. Sketch: a v2 envelope signing a domain-separated
  message (version, seq, not_after, scope, keyid, body); nein stays stateless,
  the verifier keeps the last seq per (key, scope).

**Deferred, all failing closed or documentation-only:**
- I-10 — an identifier that is an nft keyword (`fwd`) passes
  `validate_identifier`; nft refuses the batch. Needs nft's keyword list. 1.9.x.
  **Fixed in 1.9.1** (`validate_nft_name` at every bare-name position; the
  keyword list probed from nft 1.1.7, not transcribed — 160 words, 28 more for
  a ct timeout's name, 16 more for `list table`'s name, `@ll` / `@nh` /
  `flow offload @last` as references).
- I-7 (part) — `counter name "x"` names a counter object nein's table model
  cannot declare; nft refuses. 1.9.x, with named objects.
- B-8 — builder validators accept names that composed table/chain names push
  past `firewall_validate`'s 64-byte limit; the firewall then fails validation.
  1.9.x. **Fixed in 1.9.1** (engine `<id>_in` / `_out` / `_hosts`, bridge
  `<prefix>_filter` / `_nat` / `_iso` and `iso_<group>`, GeoIP `<name>_v6`;
  policy's composed rule comments against the 128-byte limit, the same class).
- B-9 (part) — the GeoIP default hook (input) does not cover forwarded or
  DNAT'd container traffic; prerouting would. A behaviour change for every
  consumer, so 1.9.x. **Fixed in 1.9.0** (default prerouting).
- B-2 (related) — engine outbound dispatch keys on `ip saddr`, which any local
  process can choose with `bind()`; socket cgroup / skuid matching would bind
  dispatch to the process. 1.9.x.
- S-8 — with SIGCHLD set to SIG_IGN, or a reaper that wins the race, apply
  returns Err after nft committed; a caller that retries an additive apply
  duplicates rules. Documented; re-diff rather than re-apply. A distinct
  "outcome unknown" code is a 1.9.x API change. **Fixed in 1.9.0**
  (`NEIN_ERR_OUTCOME_UNKNOWN`, also for a deadline kill or a signal death).
- P-8 — rule bodies are compared byte-for-byte against nft's canonical text
  (`10.0.0.5/32` lists as `10.0.0.5`), so such a chain is rebuilt on every diff:
  churn, not a security issue. 1.9.x (parse `nft -j`). **Fixed in 1.9.2**,
  without `nft -j`: the target side of the comparison is rendered in the
  spelling nft lists, and live bodies lose counter and quota state. Measured
  first: `tests/integration/diff_converge.tcyr` found 27 of 86 single-rule shape
  chains and 2 of 8 builders (bridge, NAT) churning against nft 1.1.7, among them
  every `counter` rule, whose values reset on each rebuild. All converge now.
- P-9 — `parse_rules_with_handles` matches a comment *prefix* by design
  (`agent-1` matches `agent-10`); documented — include a delimiter.

**Found while fixing I-10 / B-8 (1.9.1), both fixed there.** Probing nft for
I-10 showed the class is wider than keywords: nft 1.1.7 refuses **any name
starting with a digit or `-`** in every name position (`validate_identifier`
took `3f2a`, so an engine agent named by a hex container id composed the chain
`3f2a_in`, and the batch failed). And the builder test at the policy comment's
limit failed to load: `validate_addr` took **six IPv6 groups and a dotted quad
with no `::`** (`1:2:3:4:5:6:1.2.3.4`), which nft's scanner has no rule for. A
differential run of 2,329 generated IPv6 spellings against nft 1.1.7 disagreed
on that form and no other. Both LOW (fail closed at apply).

An independent review of the 1.9.1 change before release found four more of
the class, all fixed in 1.9.1 and all LOW:
- four keywords missing from the probed list — `eq`, `xor`, `lshift`,
  `rshift`, the operators spelled out, which nft names in its errors as
  symbols; a batched check of every lowercase name of 1–5 letters
  (12.4 million) then found nothing else;
- `nft list table <family> <name>` reads the name in a scope where `rules`,
  `tables`, `count` and 13 more are keywords, so `find_rules_by_comment` could
  not list a table it can declare;
- interface names rendered bare as flowtable `devices` and ifname set / map
  values, where nft reads `vxlan`, `bridge`, `gre` or `3eth` as a keyword or a
  number (quoted now);
- `ap_validate` and `policy_validate` never range-checked ports or protocols,
  so `ps_tcp(70000)` passed the builder and failed `firewall_validate`.

**Found while fixing P-8 (1.9.2).** The new test loads a corpus of one chain
per match and verdict shape, which no earlier test had loaded. Two of them never
loaded, so a batch that held either failed at apply (both LOW, fail closed):
- `quota … gbytes` — nft 1.1.7 has no `gbytes` unit. **Fixed in 1.9.2**: it
  renders as `N*1024 mbytes`, and a quota whose bytes pass 2^63 is refused.
- `exthdr auth exists` — nft's `exthdr` takes hbh, rt, frag, dst and mh, and
  has nothing for AH. **Fixed in 1.9.2**: `EXT_AUTH` is refused at validation.

One class is deferred (LOW, fail closed). Some rules are valid in one family
and refused in another, and `firewall_validate` does not check rules against
their table's family. The probes found `reject with icmpx …` refused in ip and
ip6 tables ("abstracted ICMP unreachable not supported"), and `reject with
icmp …` refused in an ip6 table ("conflicting protocols"). The class is wider
than reject, so it is a roadmap item, not a patch fix. **Fixed in 1.9.3**, with
the class measured first. `tests/integration/nft_family.tcyr` loaded every
object, base-chain header and rule shape in each of the six families: 197 of
684 cases validated and failed to load. 78 were in arp, 36 netdev, 26 ip6, 26
bridge, 24 ip and 7 inet. Probing the shapes under each base chain found a
second dimension: the kernel holds NAT, `reject` and `flow offload` to the
hooks of the base chains that reach them through jump / goto, and refuses 16
nested jumps and any jump to a base chain. That is 295 more cases. All are
refused at validation now, and the test's 3,557 cases agree with nft.

**Found while fixing it (1.9.3).** `tests/integration/nft_load.tcyr` judged the
builders with `nft -c`. Check mode skips the kernel's hook validation (`dnat`
in a filter chain passes it and fails a load), so "every builder loads" had
meant "every builder parses" since 1.8.2. No builder was affected: each loads
for real, and `diff_converge` has loaded them since 1.9.2. LOW, test
strength, not product code. **Fixed in 1.9.3**: `nft_load` and `nft_family`
load for real.

**Out of scope, reported to the consumer:** stiva writes its ruleset to the
fixed path `/tmp/stiva-nft-ruleset.nft` before `nft -f` — a predictable `/tmp`
path for a root process (symlink / race). Not verified here.

## The 2026-08-21 fixes, re-checked under cyrius 6.7.18

All hold: C-1 (validation on the diff path; the name gap is P-5, now closed),
H-1 (ct-state list), H-2 (`-a`), H-3 (no handle-0 delete), H-4 (no crash; its
opener list caused P-2, now replaced), H-5 (ordered rebuild — effective again
now that P-2 is fixed), H-6 (quote awareness — bypassable via `nft -j`, now
backed by P-4's balance check and end-of-line handle), H-7 (SIGPIPE), the
waitpid check, the short-write check, the src==dst redirect (now subsumed by the
copy-above-10 redirect), handle overflow, `#` in elements, the signing delimiter
and keyid checks, and every value-form `Result` site (115 `is_err_result`, 108
pair binds, 157 propagations — none of the risky forms).

## Areas audited and found clean

Every `var buf[N]` and `alloc(N)` against its accesses; struct layouts against
their accessors; the block stack bounds (40-deep nesting, slot 15 at byte 120 of
128); argv sizing and the execve-failure path; envp (empty); the nft path
(absolute, no PATH lookup); `jsonx` allocations; every validator's value-form
propagation; the 6.7.x language changes (no lone `!`, no reserved-word
identifiers, no `impl`, typed pointers or unary operators on constants);
cyrius 6.7.10–6.7.18 tooling (no CI step blinded beyond the three gates fixed in
1.8.1); bote 3.4.11–3.7.6 (no signature change or name collision against nein).
