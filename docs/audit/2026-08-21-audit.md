# Security Audit — 2026-08-21 (P(-1), v1.6.9)

Scaffold-hardening review per CLAUDE.md's P(-1) process, run against v1.6.8
(391 public fns, 21 modules, 699 assertions at review time).

**Method.** Seven independent reviewers, one per area — buffer/memory safety,
subprocess and syscall layer, nftables injection, parser robustness, the
Ed25519 signing path, functional correctness of render/diff, and documentation
accuracy. Every finding rated MEDIUM or above was then handed to a separate
adversarial verifier instructed to *refute* it: to check the failure path was
reachable from a public API rather than guarded upstream, and that the severity
was justified. 53 findings were reported; 36 went to verification; 8 were
refuted or downgraded to non-issues. Several survivors were confirmed by
building and running instrumented binaries — SIGSEGV (exit 139), SIGPIPE
(exit 141), and a hard timeout — not by reading alone.

**Result: 1 CRITICAL, 6 HIGH, 10 MEDIUM, 17 LOW confirmed.** Five of the seven
CRITICAL/HIGH are fixed in v1.6.9; the rest are recorded below with severity
and a fix sketch.

---

## Fixed in v1.6.9

### C-1 (CRITICAL) — the diff apply path performed no validation at all

**`src/lib/diff.cyr`** — `nein_diff` → `diff_compute` → `diff_target_rules` →
`diff_apply` → `apply_ruleset_str` reached `nft -f -` without ever calling
`firewall_validate` or `chain_rule_validate`. `apply_firewall`
(`apply.cyr:255`) has always validated the whole tree first; the diff path,
added at 1.5.0 and made the documented idempotent-apply entry point in the
README, did not. Every T-1 validator — comment, address, interface, chain name,
set name — was bypassed on that path.

*Failure path (reproduced):* `rule_set_comment(r, "evil\" ; flush ruleset ; #")`
on a rule in the target firewall. `firewall_validate` would reject it, but
`nein_diff` never calls it: `rule_render` emits the comment verbatim,
`_emit_add_rule` wraps it as `add rule …`, and the whole string is piped to
nft. The comment closes its own quote and appends `flush ruleset`.

*Fix:* `nein_diff` now calls `firewall_validate(target_fw)` and returns its
`Err` before anything is rendered. Independently, `diff_target_rules` now runs
`chain_rule_validate` per rule and **drops** any rule that fails, so a caller
using the lower-level `diff_compute` + `diff_apply` pair directly cannot emit
unvalidated text either. Refusing to add a rule is always safer than adding one
whose contents were never checked.

### H-1 (HIGH) — `MATCH_CT_STATE` was rendered into nft grammar unvalidated

**`src/lib/rule.cyr:498`** — `_render_match` interpolates the caller's string
straight into `ct state { … }`, but `rule_validate`'s match dispatch had **no
`MATCH_CT_STATE` branch**. `validate_ct_state` existed in `validate.cyr:173`
and threat-model **T-1 named it as the mitigation covering this field** — but a
repo-wide grep found zero production callers. The documented control did not
exist.

*Failure path:* `match_ct_state("established }\n    accept\n    ct state { new")`
passes `firewall_validate`, then renders as a closed brace followed by an
injected `accept` statement — turning a deny rule into an allow.

*Fix:* added `validate_ct_state_list` (`validate.cyr`) and wired a
`MATCH_CT_STATE` branch into `rule_validate`. The existing single-token
`validate_ct_state` could not be used directly: every real caller passes a
comma-separated list (`"established, related"`), so the new validator splits on
commas, trims each token, and checks it against the same closed set.

### H-2 (HIGH) — `nein_diff` listed the live ruleset without `-a`

**`src/lib/diff.cyr:418`, `src/lib/mcp.cyr:316`** — both called `list_ruleset()`
(argv `nft list ruleset`) rather than the `list_ruleset_with_handles()`
(`nft -a list ruleset`) that already existed alongside it. Without `-a` there
are no `# handle N` suffixes, so `_strip_handle_suffix` returned handle **0**
for every live rule.

*Failure path:* any reconciliation that must delete something emits
`delete rule inet filter input handle 0`. `diff_apply` concatenates all ops into
a single `nft -f -` transaction, so nft rejects the **entire batch** — every
add in the same run is silently discarded and the firewall never converges.

*Fix:* both call sites now use `list_ruleset_with_handles()`.

### H-3 (HIGH) — a delete op could be emitted with handle 0

**`src/lib/diff.cyr:341`** — `_emit_del_rule` formatted whatever
`live_rule_handle` returned, including the 0 that means "this line carried no
handle". Independent of H-2: any line the parser fails to attribute produces
the same batch-poisoning op.

*Fix:* `_emit_del_rule` returns 0 and logs instead of building the op, and the
caller skips a 0 rather than pushing it into `ops` — pushing a NULL would have
reached `str_builder_add_cstr`, whose `strlen(0)` is the same segfault class as
H-4.

### H-4 (HIGH) — unrecognised nft block types desynced the brace stack → SIGSEGV

**`src/lib/inspect.cyr:99`, `src/lib/diff.cyr:194`** —
`_classify_block_open` knew only `table` / `chain` / `set` / `map` /
`flowtable` / `ct timeout`. nft also emits `counter NAME {`, `quota NAME {`,
`limit NAME {`, `synproxy NAME {`, `secmark NAME {`, `ct helper NAME {` and
`ct expectation NAME {` at table level. Such a block's opening line pushed
nothing, while its closing bare `}` still popped — dropping the depth to 0
*inside* the table, which zeroed `current_family` / `current_table`. Every rule
parsed after that point was built by `_live_rule_new(0, 0, …)`, and those NULL
pointers went straight to `streq` → `strlen(0)`.

*Failure path (reproduced, exit 139):* a live ruleset containing any
table-level `counter` block — which is ordinary nft output — segfaults the
calling process during `nein_diff`.

*Fix:* two independent changes, both applied. `_classify_block_open` now
recognises all seven remaining openers as a new `BLOCK_OTHER` kind; and the
rule-push site refuses to build a `LiveRule` with a NULL family, table or
chain, logging and skipping instead. The second guard means an opener
introduced by a *future* nft release degrades to a dropped rule rather than a
crash.

**Tests added:** 30 assertions across `test_ct_state_validation`,
`test_diff_validates_target`, `test_diff_del_op_requires_handle`, and
`test_parser_block_desync` — the last replaying the exact input that produced
exit 139. Suite: 699 → 729.

## Open — HIGH

### H-5 — `diff_compute` ignores rule position

**`src/lib/diff.cyr:357`.** The diff treats a chain as an unordered set:
`_target_in_live` matches on (family, table, chain, body) only, and every miss
becomes `add rule …`, which nft **appends**. Rule order is nftables' evaluation
semantics, so a partial diff can leave a chain matching neither the old nor the
target ruleset. `diff.cyr`'s own header claims the byte-equality strategy is
"conservative but always correct" — that claim is false for any chain where the
target inserts a rule anywhere but the tail.

*Failure path:* live `input` = [`ip saddr 10.0.0.0/8 accept`]. Target =
[`ip saddr 10.0.0.5/32 drop`, `ip saddr 10.0.0.0/8 accept`]. The accept already
matches, so only the drop is emitted — and it lands **after** the accept it was
meant to precede. The host stays permitted.

*Fix sketch:* compare position as well as body, and emit ordered ops using
`insert rule … index N` / `add rule … position HANDLE` (`add_rule_after_live`
already exists). Cheaper interim: when any rule in a chain differs, delete and
re-add the whole chain in order. Correct the header comment either way.

### H-6 — `_strip_handle_suffix` has no quote awareness

**`src/lib/diff.cyr:110`.** Scans backwards for the last textual `" # handle "`
with no notion of quoted strings, so a rule comment containing that literal
text is mistaken for the handle suffix. Body and handle both come out wrong,
and the mis-parsed rule then drives add/delete decisions.

*Fix sketch:* only accept the marker when it sits outside a quoted region —
track quote state scanning forward, or require the suffix to be the trailing
token after the final unquoted `#`.

### H-7 — SIGPIPE is never ignored: a dead nft kills the host process

**`src/lib/apply.cyr:105`.** The parent writes the ruleset with a flagless
`sys_write` and nein never installs a SIGPIPE ignore. If the nft child is gone
when the write lands, the kernel's default disposition terminates **the whole
calling process** — not just the apply. Confirmed by reproduction (exit 141).
The stdlib ships the fix at `lib/syscalls.cyr:80-106` (`signal_ignore(13)`).
This also falsifies T-4's claim that on execve failure "the parent observes
that exit status and returns `Err(ERR_PERMISSION_DENIED)`".

*Fix sketch:* `signal_ignore(13)` once before the write loop, then treat
`-EPIPE` as a hard error.

## Open — MEDIUM (selected)

- **`sys_waitpid` return unchecked** (`apply.cyr:118`, `:199`). On failure
  `status` is left 0, which `WIFEXITED(0)==1` / `WEXITSTATUS(0)==0` decodes as
  a clean success — so a failed apply can report `Ok`. Reachable when a
  consumer installs a SIGCHLD reaper, which supervisors like stiva and daimon
  do. *Rated CRITICAL by the reviewer, MEDIUM after verification.*
- **Truncated stdin write reported as success** (`apply.cyr:106`). The loop
  breaks on `n <= 0` and never compares `written` against `input_len`; if the
  truncated prefix happens to parse, nft applies it and exits 0.
- **Child clobbers its own stdio when a pipe fd lands on 0/1/2**
  (`apply.cyr:82`, `:174`). `sys_dup2(src, N)` followed by unconditional
  `sys_close(src)` destroys the descriptor when `src == N` — reachable on a
  daemonized host that closed fds 0-2. `dup2` returns are unchecked.
- **Pipe-ordering deadlock** (`apply.cyr:104`). The full ruleset is written
  before stderr is drained; both pipes can fill. Verified *not* reachable with
  real nft (needs >64 KiB of stderr), hence MEDIUM.
- **Handle integer overflow** (`diff.cyr:140`). `handle = handle * 10 + …` with
  no bound; 20 digits wrap and emit a `delete rule … handle <wrapped>` that can
  target an unrelated rule.
- **Signed-ruleset delimiter injection** (`sign.cyr`). A rule comment of
  `-----END NFT RULESET-----` passes `validate_comment` and can truncate the
  signed body. Confirmed by PoC.
- **`nein-sig-keyid` header ungated** (`sign.cyr:176`). No charset or length
  check, and it sits outside the signed body.
- **`#` is absent from the dangerous-character set** (`validate.cyr:13`).
  Verified against nftables 1.1.6: `… accept # drop` applies as **accept** —
  the intended verdict silently vanishes. Reachable through
  `validate_nft_element` (which `add_rule_live` uses) and set-lookup fields.
  Other `#` sites sit inside `{ }` and fail closed as a parse error.

## Areas audited and found clean

- **Buffer bounds.** Every `var NAME[N]`, every `alloc(N)` against its
  documented layout and every offset used repo-wide, every `memcpy`, every
  pointer walk, and all size arithmetic. No out-of-bounds access found. The
  v1.5.5 block-stack sizing is exactly right (16 slots, depth clamped `< 15`
  on push and `> 0` on pop, max offset 120 of 128).
- **fd accounting in `apply.cyr`.** Every early return closes exactly the
  descriptors open at that point; no leak on any path.
- **argv sizing.** All four vectors correctly sized including the NULL
  terminator.
- **execve-failure child path.** Cannot fall through into parent code.
- **MCP argument handling.** Every field reaching nft is validated before
  interpolation and re-validated by `add_rule_live`; `jsonx` allocates fresh
  buffers per call, so there is no static-buffer aliasing between the validate
  pass and the build pass.
- **The 1.6.7 anonymous-set helpers.** `rule_matching_ports` /
  `_rule_addr_set` correctly validate every element before any mutation.
- **Backslash handling.** Not an escape inside nft quoted strings in 1.1.6, so
  quoted contexts are safe once `"` is rejected.
